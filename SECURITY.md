# Security Policy

This policy applies to every repository owned by **StephaneBerthoz** that does not ship its own
`SECURITY.md`. A repository-level policy, when present, takes precedence.

## Reporting a vulnerability

**Do not** open a public issue, discussion or pull request for security reports.

- If the repository shows **Report a vulnerability** in its *Security* tab, use it
  (GitHub private vulnerability reporting).
- Otherwise, email the maintainer: **stephane.berthoz@gmail.com**

Please include:

- The affected repository and version, tag or commit
- A description of the issue and its security impact
- Reproduction steps (proof of concept, scripts, sample payloads)
- Whether you would like to be credited

You can expect:

- An acknowledgement within **5 business days**
- A triage update within **10 business days**
- A coordinated disclosure timeline once the severity is agreed

## Supported versions

Only the latest release, or the default branch when there is no release, receives security fixes.

## Good faith

Test only against systems and data you own. Do not access, modify or exfiltrate data that is not
yours, and do not degrade the availability of any service.
